# RSI 重复测试与难度阶梯 v0.2

2026-09-30。此设计在本批真实 Claude 调用前固定，作为探索性工程/方法筛选，非正式预注册。

## 设计

沿用已保存的南肯辛顿太阳辐照输入；不修改物理求解器。两个独立调用序列依次完成三个等级，每级产生一个候选修改。每个等级有独立确定性构建的开发、晋升验证和最终任务。任务候选 ID 分别打乱，降低记忆站点 ID 的帮助；底层城市几何/太阳数据仍然共用，因此不称为独立天气或城市泛化。

| 等级 | 任务 | 冬季损失上限 | 每 episode 评价预算 |
| --- | --- | ---: | ---: |
| L1 | 8 候选，最多 1 块板，等成本 | 1.2% | 4 |
| L2 | 12 候选，最多 2 块板，不等成本、总成本 4、禁用站点 | 0.8% | 5 |
| L3 | 15 位置各两种尺寸，共 30 选项；最多 3 块板，总成本 6、禁用选项 | 0.5% | 6 |

L3 的尺寸为既有 12×12 m 候选及其中心嵌套的 6×6 m 板，不扩大到原先未筛选的地块。同位置尺寸选项不能同时建设；真实阴影交互由原求解器的遮挡并集计算，不强加可加性。成本单位为合成相对成本，不是货币。难度排序首先按结构复杂性预设，实际是否区分方法由结果判断。

## 重复与继承

- 每个候选与父代在晋升任务上各运行两次，交替先后顺序。没有可控的模型采样种子，不把请求编号称作随机种子。
- 所有候选提交必须有效，各任务平均分不下降，总平均收益严格提高超过 1e-6 才晋升。两次重复只是初步抑制波动，不能宣称统计显著。
- 下一级只继承前一级获准且冻结的 Agent，不继承最终评分；保存跨运行来源及原始冻结版本。没有晋升也按计划进入下一级，不为得到正结果临时换任务或放宽门槛。
- 每条序列的三个等级全部完成进化并冻结后，才开始最终评分。
- 最终任务比较冻结版本与最初固定 Agent，各两次；最终分数不反馈到任何更新流程。
- 同步保留所有被拒绝修改、无效动作、未提交和调用失败。

共 2 条序列 × 3 级 = 6 个小实验，6 次候选修改，24 次父子晋升验证 episode，24 次最终 episode（其中 12 次固定 Agent 对照），加 6 次开发 episode。有效运行总计 54 个 episode。各 episode 最多预算+2 次模型动作；每候选另一次模型修改调用。总后端调用上界为 384 次（实际可提前提交而减少），无自动重试。Claude 的单次后端调用可能包含多个内部轮次，另记录。

## 对照和评价

最终决策完成后，控制器独立计算每级最终任务的随机搜索（10 seeds）、单点排序（确定性一次）、受约束 GP 搜索（10 seeds），这些在线方法与对应 Agent episode 使用相同物理评价预算。完整枚举仅作为预算外开发参考，先按开发指标选择，再评价原时间留出。禁止把枚举结果发送给 Agent。

主指标为独立评分下、满足全部约束的夏季直接辐照削减；无效/未提交的运行保留并计为零有效收益，同时单独报告。辅助指标为非空可行提交率、冬季违反、最优参考差距、评价/模型调用数、tokens 和成本。分别报告部署成本、进化开销与累计跨等级开销；固定 Agent 对照只是部署预算匹配，不能据此声称全流程同成本优势。

不要把跨等级原始收益曲线当成能力曲线：候选、约束和预算都变了。只在同级同任务比较方法；两个序列与每序列两个最终重复数量较小，仅报告逐次结果及描述性汇总，不做伪精确显著性推断。

## 完成与停止

先跑合成模型替身验证继承和批处理，再固定代码运行 Claude。模型接口、输入或代码校验失败时保留失败，不冒称任务通过；排查与修复必须新建运行且说明版本变化。完整报告包括任务构造身份、协议运行包、所有结果、代码测试和图表。不发布数据。

## 运行中接口修复记录（v0.2b）

初次真实运行的两条序列均完成 L1 冻结；L2 修改请求均用满 4,096 输出 token，Claude Code 返回 `error_max_structured_output_retries`。保留原始失败状态、请求/响应和费用。未释放任何最终评分时，将新 L2/L3 配置的单次输出上限提高到 16,384，复用已冻结且未最终测试的 L1；物理评价预算、任务、评分和晋升规则不变。原始失败的 14 次调用及 12 次计费评价另计，不能从总成本中扣除。输出容量改变属于接口配置修复，不能称为严格同计算预算复现。

v0.2b 的序列 1 仍在 L2 修改调用遇到结构化输出错误，这次返回零 usage，不能归因为 token 截断。追加一次相同配置的完整 L2 尝试；保留第二次失败全部证据及费用。该重试不是根据最终分数挑选版本；此时序列 1 尚无任何最终评分。若再次失败，按失败报告，不无限重复。

## 本批归档后的工程修复

六个真实运行均完成、冻结并导出后，修复模型异常且无返回值时的未知费用计数（与未知用量一同标记）。相应故障回归用例已先复现失败再验证修复。后续新建运行的默认输出容量改为 16,384；本批既有配置、日志、结果和源码快照保持原样。以上工程修复没有参与本批已完成决策，不可把归档结果描述为新版代码重新跑出的结果。
