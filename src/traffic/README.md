# User Manual

This manual explains how to **use and reproduce** this code.

All commands are run from the `project/` directory.

## 1. Environment Setup

- Python 3.8+
- Install dependencies:

```bash
pip install -r ../requirements.txt
```

## 2. Quick Start

```bash
cd project

# ① Train a complex road-network model
python train.py

# ② Evaluate this model; pass the date obtained above to --model
python evaluate.py --model <training date>
```

Training results appear in the `train/` directory: `best_model_{date}.pt` (model weights) and `train_log_{date}.txt` (training log), where the date defaults to the current time (see §3.2).

## 3. Operation Details

### 3.1 Generate Simulation Data

For memory reasons, data is **generated on the fly during training/evaluation and is not saved to disk**. The two data generators:

| Scenario | Command | Description |
|---|---|---|
| Complex intersection | `python data/generate_complex.py` | 12 feature channels|
| Single intersection | `python data/generate_intersection.py` | 11 feature channels|

To adjust the data volume/scenario, edit `configs/default.py` (see §4).

### 3.2 Train the Model

```bash
python train.py
```

- **The filename date defaults to the current time** (format `MM-DD_HH-MM-SS`)
- Set the environment variable `LOG_DATE` only when you want a fixed, predictable filename, for example:
  ```bash
  LOG_DATE=08-27_00-00-00 python train.py
  ```
- Outputs: `train/best_model_{date}.pt` + `train/train_log_{date}.txt`.
- Trains 250 epochs by default, with 2000 training trajectories + 200 validation trajectories (changeable in `configs/default.py`).
- On an HPC cluster you can submit via `train.pbs`.

### 3.3 Evaluate the Model

```bash
python evaluate.py --model <the model date you want to evaluate>
```

- `--model` takes the **date portion** of the model file (e.g. `08-16_07-31-30`).
- Output metrics: ADE (Average Displacement Error), FDE (Final Displacement Error).
- The metric values are normalized; to get the actual distance multiply by `GRID_SIZE*CELL_SIZE`. For example, the `ADE` of `My model (No-iteration)` in the final report is computed as `0.019192*56*3=3.224256`

### 3.4 Validate on the Real London Road Network

```bash
# ① Convert the raw OSM road network (roads.geojson) into a grid representation usable by the model
python verification/convert_london.py
#    produces verification/london_roads.json

# ② Use the trained model for single-window prediction and export as lon/lat trajectories
python verification/export_prediction.py 0
#    produces verification/predictions.json
```

- In step ② the model path is hard-coded in `export_prediction.py` (currently `train/best_model_08-16_07-31-30.pt`, a 12-channel complex-scenario model). To use a different model, change the line that loads the model in `export_prediction.py`.
- Dependent files: `generate_complex_london.py`, `particle_mlp_london.py`, `london_utils.py` are all imported automatically by `export_prediction.py`.

The `top_all.mp4` file under the `verification` folder is the 2D animation generated by Xinyang's model based on my predictions in the final report; `city_sk2_anim.glb` is the script for launching the 3D animation, which needs to be imported into https://gltf-viewer.donmccurdy.com for preview.

### 3.5 Compute Emissions + Optimize Signal Control

```bash
python emission.py --sample 0 --model <the model date to evaluate> --init 5 --iter 15
```

- Based on the VSP emission model + Bayesian optimization, it automatically searches for the optimal `speed_factor` (∈ [0.3, 1.0]) to minimize emissions.
- `--sample`: which sample to use; `--init`: initial random points for Bayesian optimization; `--iter`: number of optimization iterations.
- This script uses the **single-intersection** dataset (`data.generate_intersection`).

### 3.6 Visualization

#### 3.6.1 Single-intersection scenario

```bash
# Static prediction image
python visualization/visualize_simple_prediction.py -s 0 -m <single-intersection model date>
# Animation
python visualization/visualize_simple_prediction.py -s 0 -m <single-intersection model date> -a
```

- Outputs: `plot_pred_s{sample}.png` (static), `anim_pred_s{sample}.gif` (animation).
- The single-intersection model is **11-channel**; before using it, remove `+ DRIVABLE_DIM` from `TOTAL_FEAT_DIM` in `configs/default.py` (see §5.1).

#### 3.6.2 Complex road-network scenario

```bash
# Static prediction image
python visualization/visualize_complex_prediction.py -s 0 -m <complex model date>
# Animation
python visualization/visualize_complex_prediction.py -s 0 -m <complex model date> -a
```

- Outputs: `complex_pred_s{sample}.png` (static), `complex_anim_s{sample}.gif` (animation).
- The complex road network is **12-channel** (includes `DRIVABLE_DIM`); the default config works as-is.

## 4. Changing Parameters

`configs/default.py`

| Parameter | Meaning | Default |
|---|---|---|
| `GRID_SIZE` | Simulation grid side length | 56 |
| `WINDOW_SIZE` | Observation window side length | 19 |
| `HIST_STEPS` / `PRED_STEPS` | History steps / prediction steps | 10 / 6 |
| `EPOCHS` | Training epochs | 250 |
| `TRAIN_TRAJECTORIES` / `VAL_TRAJECTORIES` | Number of train/val trajectories | 2000 / 200 |
| `TOTAL_FEAT_DIM` | Number of feature channels | 12 (see §5.1) |


## 5. Notes Before Use

### 5.1 The current default is the "complex scenario" — how to switch to the "single intersection"

- Currently both `train.py` and `evaluate.py` train/evaluate the **complex scenario**.
- To switch to the single-intersection model, change two places:

1. In `configs/default.py`, remove the trailing `+ DRIVABLE_DIM` from `TOTAL_FEAT_DIM`.
2. In `train.py` and `evaluate.py`, change `from data.generate_complex import generate_dataset` to `from data.generate_intersection import generate_dataset`.

Then train as usual.

## 6. Where the Final Report Table Metrics Come From

After training your own model, to get the same kind of metrics as in the final report, use the scripts below. Results are printed to the terminal; `evaluate.py` also writes to `train/eval_log_{date}.txt`.

### Table 1 — ADE / FDE (baseline comparison)

Source: `evaluate.py`

```bash
python evaluate.py --model <your model date>
```

The printed ADE/FDE are normalized values; multiply by `GRID_SIZE × CELL_SIZE` (=168) to get meters (see §3.3).

### Table 2 — Direction Accuracy

Source: `analyze_turn_direction.py`

```bash
python analyze_turn_direction.py -m best_model_<date>.pt
```

- It uses the single-intersection dataset (`data.generate_intersection`).

### Table 3 — ∆ADE / Terminal Displacement / Affected Vehicles (control intervention)

Source: `evaluate_counterfactual()` in `evaluate.py`

```bash
python evaluate.py --model <your model date>
```

- `∆ADE` = (intervention ADE − original ADE) / original ADE

### Figure 2 - Complex road-network traffic flow

```bash
python visualization/visualize_traffic_complex.py
```

### Figure 3 - Training line chart (loss curve)

```bash
python plot_training_loss.py --log train/train_log_<date>.txt
```
